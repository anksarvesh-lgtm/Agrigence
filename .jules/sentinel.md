## 2024-05-18 - [CRITICAL] Remote Code Execution (RCE) in pipeline transform
**Vulnerability:** The `applyTransform` function in `services/pipelineEngine.ts` used `eval()` to execute user-provided math operations without input sanitization, allowing arbitrary code execution (e.g., `process.exit(1)`).
**Learning:** `eval()` is highly dangerous for executing dynamically constructed strings containing user input. While migrating to a safer evaluation method (like `new Function()`), it's crucial to implement strict allowlists. Moreover, the input regex must be carefully designed so as not to break legitimate use cases such as scientific notation (e.g., `1e-5`), which can inadvertently cause functional regressions if omitted.
**Prevention:** Avoid `eval()`. Use specialized safe math parsers (like `mathjs`) in production. If `new Function()` must be used for prototyping, always validate the input string against a strict regex whitelist (e.g., `/^[-+*/().\s\deE]+$/`) to guarantee only safe mathematical tokens are permitted.
